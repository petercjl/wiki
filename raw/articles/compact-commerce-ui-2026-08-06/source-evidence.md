## 来源范围

- 2026-08-06 的网页 UI 方向探索、模板对比与用户反馈。
- 先后测试“植物图鉴社”与“紧凑插件面板”两种方向。
- 参考成品：`reference-report.html`。
- 两张用户标注截图：`../../assets/compact-commerce-ui-2026-08-06/01-font-legibility.png` 与 `../../assets/compact-commerce-ui-2026-08-06/02-layout-pillars.png`。

## 测试结论

1. 温暖、自然、杂志化的“植物图鉴社”具有鲜明审美，但不适合作为电商经营数据报告的默认表达；它会弱化操作密度、业务状态和数据决策感。
2. “紧凑插件面板”更符合电商行业报告、经营工作台、SaaS 后台和网页插件的需求：信息密度高、层级稳定、状态明确、可快速扫描。
3. 第一版紧凑面板的整体结构、配色和字体方向正确，但小字号影响阅读。两轮调整后确认：正式业务信息不得为了“紧凑”而低于舒适阅读线。
4. 页面风格的可继承对象不是某一份完整 HTML，而是布局支柱、设计变量、组件模式、内容规则、反模式和验收标准。

## 用户明确确认的四个布局支柱

### 1. 左侧主菜单

当报告或网页需要分多个区域展示时，必须使用左侧菜单栏组织。菜单承载产品或报告身份、页面导航和快捷操作；桌面端优先常驻，小屏可折叠。

### 2. 左下角核心信息区

左下角放置跨页面持续可见的全局核心信息，例如业务状态、数据规模、样本成熟度、更新时间、异常数量或数据来源。它不是普通页脚，而是状态摘要。

### 3. 右上角全局工具区

报告存在搜索、快速跳转、时间范围、账号切换、导出或刷新等元素时，优先放在右上角。推荐顺序为“搜索或快速跳转 → 时间范围 → 其他全局操作”。不存在的功能不强行占位。

### 4. 中央豆腐块模块区

主体内容以规则、紧凑、可组合的矩形模块构成。小块用于 KPI 与状态，中块用于行动建议和异常清单，大块用于趋势与表格，通栏块用于提醒和关键结论。模块大小必须表达信息层级，不能把所有卡片做成同样权重。

## 已确认的视觉语言

- 页面气质：专业、紧凑、理性、克制、可信，不冷漠。
- 页面背景：浅灰；内容面板：白色；边框：低对比灰。
- 主色：商务蓝；成功、警告、风险分别使用绿、琥珀和红。
- 圆角小而克制，避免过度胶囊化和娱乐化。
- 字体优先系统无衬线，数字使用等宽数字特性。
- 重要文本在 100% 缩放下可直接阅读；用户需要阅读的信息原则上不小于 12px。

## 参考尺寸基线

- 侧栏宽度：约 230px。
- 顶栏高度：约 66px。
- 页面主内边距：约 24px。
- 模块间距：8–12px。
- 圆角：7–10px。
- 页面标题：约 25px。
- KPI 数字：约 26px。
- 卡片标题：15px。
- 正文与表格：13px。
- 次级说明：12px。
- 10–11px 只允许用于键盘提示或非关键微型界面文字。
- 表格正文行高：约 50px；表头高度：约 44px。
- 正文行高：1.5–1.65。

## 页面骨架

```text
左侧导航
  ├─ 顶部：产品 / 报告身份
  ├─ 中部：视图导航与快捷操作
  └─ 底部：全局核心状态

右侧工作区
  ├─ 顶栏：页面身份 + 搜索 / 时间 / 全局操作
  ├─ 页面标题与业务操作
  ├─ 样本或风险提醒
  ├─ KPI 豆腐块
  ├─ 趋势分析 + 优先处理
  ├─ 时间对比 + 信号快照
  └─ 可筛选明细表 / 详情抽屉 / 其他业务模块
```

## 适用边界

默认适用：电商经营报告、营销投放报告、经营分析 SaaS、插件侧边面板、运营监控台、内部数据工具。

不应机械套用：品牌故事页、活动落地页、作品集、内容杂志、情绪型视觉页面。此类任务可以复用可读性与信息层级规则，但不必使用工作台骨架。
