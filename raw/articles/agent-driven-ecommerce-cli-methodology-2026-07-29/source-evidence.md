# Agent 驱动型电商 CLI 方法论：源证据

采集日期：2026-07-29  
来源类型：用户决策、本机 tbcli 仓库、已验证发布记录  
语言：中文  

## 用户明确决策

1. tbcli 不应只被视为淘宝专用工具案例，而应沉淀为以后开发同类 CLI 的规范。
2. 方法论应适用于不同电商渠道，例如：
   - `tbcli`：淘宝/天猫
   - `dycli`：抖音电商
   - `jdcli`：京东
   - `alicli`：阿里巴巴/1688
3. CLI 的业务能力要从电商人的视角描述，而不是从 API 或代码模块的视角描述。
4. 用户应能先问 Agent“这个 CLI 有哪些能力”，再由 Agent 调用对应稳定命令。
5. 每次 API 请求之间必须加入随机延时。
6. 遇到未登录、验证码、滑块、安全验证、访问受限或风控信号时必须停止。
7. 新能力应进入正式 CLI 命令，而不是长期依赖一次性探测脚本。
8. CLI 固定由 Codex 协助开发，因此开发规范应能被 Codex 持续读取并由测试约束。

## tbcli 当前实证

仓库：`/Users/pechen/.local/share/tbcli`  
公开 npm 包：`@petercjl/tbcli`  
已发布版本：`0.4.0`  
已发布 GitHub Release：`v0.4.0`  

### 运行与分发

- Node.js 包通过 `npm install -g @petercjl/tbcli` 安装和更新。
- `package.json` 要求 Node.js 20 或更高版本。
- npm 安装 JavaScript 依赖；Node.js 和 Google Chrome 是系统前置条件。
- macOS 与 Windows 共用一套业务命令，平台差异集中在 Chrome 路径和用户目录解析。
- GitHub Release 触发 GitHub Actions，在 `npm ci`、`npm test` 通过后使用 OIDC 发布 npm，不依赖每次人工输入 2FA。

### Agent 与 CLI 的职责

- 用户用自然语言描述业务目标。
- Agent 查询 `capabilities --json`，补足必要输入并选择稳定命令。
- CLI 负责确定性执行、登录检查、请求安全、数据规范化、文件生成和退出码。
- 浏览器打开、环境诊断、页面检查和接口捕获属于内部或开发能力，不应混入普通用户的业务能力列表。

### 能力自描述

当前本地改造使用统一命令注册表生成：

- `tbcli capabilities`：面向电商业务人员。
- `tbcli capabilities --json`：面向 Agent。
- `tbcli capabilities --all`：额外展示内部与开发工具。

每个稳定业务能力登记：

- 业务名称
- 业务描述
- 自然语言示例
- 必填输入
- 可选输入
- 交付结果
- CLI 命令模板

代表性示例：

> 帮我获取【店铺首页链接】的商品列表

### 浏览器与会话

- 使用专用 Chrome 调试实例，而不是临时浏览器身份。
- 默认 CDP 地址：`http://127.0.0.1:9223`。
- 默认用户目录：`.dianshang-chrome-profile`。
- CLI 自动探测并启动 Chrome，复用持久登录状态。
- CLI 不导出或另存 Cookie；数据请求在已登录浏览器页面上下文中执行。

### 请求安全

当前本地改造将安全规则集中到公共模块：

1. 稳定数据命令先进入已认证会话。
2. API 请求和重试前执行随机延时，默认 1000—2000ms。
3. 等待前后检查页面是否出现登录或验证信号。
4. 响应后再次识别登录重定向、验证码、滑块、访问受限和接口风控信号。
5. 命中风险信号立即停止；不继续翻页、不刷新绕过、不对风险错误重试。
6. 普通网络瞬时错误可以有界重试，但每次重试仍需重新经过安全策略。

### 开发与稳定能力

- `dev pages`：查看可用页面。
- `dev inspect`：检查页面能力和必要上下文。
- `dev capture`：限时捕获受限范围内的请求元数据。
- 捕获记录对敏感查询参数脱敏，不导出 Cookie 和响应正文。
- 探索成功且需求会复用时，应把能力折回正式命令、参数、测试和能力注册表。

### 商品列表案例

- 优先调用页面使用的结构化接口获取分页商品数据。
- 接口价格可能是前端混淆值，不能直接作为最终业务价格。
- 页面能显示明文价格，说明浏览器运行时存在可验证的还原路径。
- 已验证路径包括动态字体字形映射、店铺页面价格匹配，以及按精确商品 ID 进入详情页补充。
- 匹配必须校验商品 ID；价格不能完整获取时停止交付，不能编造。
- OCR 只作为结构化接口、运行时数据和真实渲染路径均不可用时的最后降级。

### 交付物

- JSON/CSV 可以服务开发、程序组合或中间检查。
- 面向业务人员的 Excel 只保留最终可理解字段。
- 商品 Excel 当前包含：概览、商品列表、SKU 明细。
- 最终交付不暴露 API分页、请求延时、价格解码状态、原始编码价格和页面混淆字符等内部细节。

### 测试与治理

- 单元测试覆盖 Chrome 跨平台路径、登录判断、验证信号、随机延时边界、价格还原、数据规范化和 Excel 结构。
- 能力注册表测试检查所有路由命令均已登记，稳定业务能力必须包含完整的业务说明。
- `AGENTS.md` 记录 Codex 开发规则。
- 公共代码提供安全默认值。
- 自动测试作为发布阻断门。
- 发布前运行 `npm test` 和 `npm pack --dry-run`，并进行 npm 包全新安装验证。

## 可迁移边界

以下属于跨平台核心：

- Agent 与 CLI 分工
- 能力自描述
- 命令注册表
- 浏览器会话抽象
- 登录、延时、验证停止和高影响操作确认
- 开发探测到稳定命令的演化
- 数据规范化与最终交付分层
- 测试、版本、发布和治理

以下必须由渠道适配器实现：

- 浏览器入口和登录态识别
- 平台域名与风险信号
- 接口签名、请求协议和分页方式
- 页面结构与渲染数据
- 字段映射和业务术语
- 写入动作的提交、回滚和幂等方式

## 尚未完成或需要继续设计

- 当前能力注册表和统一请求安全策略仍是 tbcli 仓库中的未发布修改。
- 首次未登录时，CLI 会停止并要求登录后重跑，尚未实现安全的等待与恢复协议。
- 当前优先支持 Chrome；是否支持其他浏览器需单独验证。
- 网页填写能力尚未形成完整规范，需要补充预览、显式确认、幂等键、防重复提交、结果回读和审计记录。
- 删除、退款、改价、发布、批量写入等高影响动作必须按风险等级增加确认和恢复机制。
