| --- | --- |
| 00:00–00:20 | 有没有这种感觉：只写一句提示词——“一个女生在海边走”，模型还挺稳定；但一旦加入细节：27 岁、短发、卡其色风衣、逆光、慢推镜头、表情克制、电影感、黄昏海岸，它就开始乱加细节、丢设定，甚至画面崩掉。 |
| 00:20–00:28 | 为什么提示词越具体，模型反而越不听话？因为提示词没有进行分层控制。 |
| 00:28–00:38 | 这不是玄学，也不是提示词写得不好。做过几次 A/B 测试就会发现，背后是一个理性的工程问题。 |
| 00:38–00:45 | 生成模型不是逐条执行命令，而是在有限计算预算、有限步数里做约束满足、寻找可行结果。 |
| 00:45–00:57 | Prompt 服从度，是文本条件能在多大程度上约束生成结果的语义、构图、运动和风格。 |
| 00:57–01:09 | 对视频生成系统来说，Prompt 通常先被文本编码器压缩成一组向量，再通过交叉注意力、条件引导等机制影响每一步去噪。 |
| 01:09–01:16 | 模型看到的不是一张执行清单，而是一组高维语义向量。 |
| 01:16–01:34 | 它不会像导演助理一样逐条核对短发、风衣和慢推镜头，而是在概率分布中寻找既符合文本条件、又看起来像真实视频的结果。条件越多，问题越接近多目标优化。 |
| 01:34–01:45 | 当年龄、发型、服装、焦段、运镜和情绪表演都被要求同时成立，每一项都会占用模型的表达能力和注意力资源。 |
| 01:45–02:03 | 条件之间还可能不兼容：35mm 广角感与面部特写会在构图上拉扯；逆光剪影与清晰表情会在光照上冲突。模型不是故意忽略，而是在冲突条件中自动取舍。 |
| 02:03–02:10 | 各种提示词约束会互相争抢资源。在视频生成中，压力主要发生在三个层面。 |
| 02:10–02:36 | 第一层是文本编码的压缩损失。Prompt 再长也要进入文本编码器；长句并列修饰、抽象风格词与具体物体词被压进同一语义空间。模型可能抓住“海边、女性、电影感”等强信号，却弱化“卡其色、27 岁、表情克制”等细粒度信号。 |
| 02:36–02:47 | 第二层是条件引导与画面质量之间的张力。很多扩散系统会采用类似 CFG 的条件引导，把生成结果往文本描述上拉。 |
| 02:47–03:03 | 引导太弱，画面自然但不够听话；引导太强，语义更贴近 Prompt，却容易出现过饱和、纹理噪声、肢体异常和面部不稳定。像遛狗一样，绳子太松会乱跑，太紧又会走得变形。 |
| 03:03–03:16 | 第三层是视频比图片多了时间维度。图片只需一帧成立；视频要让角色、服装、光线、背景和运动在几十帧中连续成立。 |
| 03:16–03:36 | 大量局部细节不仅要逐一生成，还要在几十帧中始终一致、不发生漂移。提示词越细越不听话，并不是“越详细越差”，而是未经分层的详细会让模型同时承担太多目标。 |
| 03:36–03:46 | 提高模型服从度时，第一层先写硬约束：主体、场景、动作、镜头目标。 |
| 03:46–03:53 | 示例：“短发女性在黄昏海边缓慢行走，镜头从中景缓慢推进。” |
| 03:53–04:02 | 第二层再写少量关键细节：服装、光线、情绪。示例：“卡其色风衣、逆光边缘光、表情克制。” |
| 04:02–04:11 | 第三层最后写风格，不要让风格词淹没结构词。示例：“写实电影质感、自然运动、稳定时序。” |
| 04:11–04:24 | 如果一个镜头必须控制很多细节，不要指望一条 Prompt 全包。更稳的方法是拆镜头、拆阶段：先锁主体和构图，再做风格和运动。 |
| 04:24–04:30 | 必要时使用参考图、首尾帧、遮罩或后期校正，分担 Prompt 的压力。 |
| 04:30–04:40 | 真正的 Prompt 强控不是写得更长、更细，而是让模型知道先听谁、后听谁，哪些绝对不能错。懂一点底层原理，画面会越来越听话。 |
| 04:40–04:41 | 结束语：“我们下期见。” |
