# 遗漏审计

## 已覆盖范围

- 格式系统：语义、导航、视觉、页面四层。
- 关键组件：标题、正文、列表、引语、目录、页眉页脚、题注、表格、图表、图像、分节。
- 使用场景：报告、提案、备忘录、SOP/教程、研究长文。
- 模板机制：内容骨架、样式映射、复杂度分层、示例内容、资产管理和发布检查。
- 可读性：扫描、定位、连续阅读、数据理解、辅助技术访问和最终发布。

## 有意不进入正式页的内容

- Microsoft 模板站不断变化的具体模板名称和缩略图：时效强，只保留稳定类型。
- DWP、DfT 和大学的机构专用提交流程：不具备跨场景迁移价值。
- GitHub Docs 的网页前置字段：保留内容类型方法，不复制平台实现。
- Wordinator 的安装、转换命令和依赖：用户已明确本研究不以生成工具为中心。

## 当前不足

- 中文正文、标题、数字和英文字母混排的字体选择尚缺可靠来源。
- 经营复盘、内部内参、咨询报告和电商运营报告的真实优秀样本尚未系统采集。
- Word 原生功能的完整格式图鉴仍需补充：主题、样式集、列表模板、文档部件、域、内容控件、脚注尾注、书签、保护与协作。
- 缺少模板反向拆解样本：尚未读取公开 DOCX/DOTX 的 `styles.xml`、主题、节属性和样式使用频率。
- 格式审计的量化阈值尚未定义，例如字体数量、颜色数量、标题跳级、直接格式占比和孤行寡行。

## 已解决的落位问题

- 用户已确认正式位置为 `domains/AI Agent工程/格式化文档/`。
- 当前先建立 Word 的通用格式系统，同时把“经营失误复盘内参”设为后续第一个真实验证样本。

## 后续研究队列

1. 补充 Microsoft Word 官方功能文档，完成格式能力地图。
2. 采集中文企业报告、复盘、内参与咨询报告样本。
3. 建立模板拆解表：文档任务、读者、页面原型、样式表、组件、节奏、禁用项、验收项。
4. 从真实 DOCX 样本抽取样式和页面设置，验证“菜谱”是否能被可靠复用。
