# 从找货到采购铺货的意图路由与工作流

## 阶段路由

| 用户阶段 | 路由 |
| --- | --- |
| 看货、找同款、比价 | `1688-product-find` |
| 查供应商、工厂、产业带 | `1688-source-suppliers` |
| 有品名、数量和要求，但无具体商品/供应商，想匹配报价 | `1688 采购询盘寻源` |
| 已有商品，准备分销到下游店铺 | `1688 分销` 或 `1688-shopkeeper` |
| 招商活动、建议价、报名、商机 | `1688-marketing-skill` |
| 88 生意通采购单 | `88 生意通` |

已有具体商品要下单不属于采购询盘；来源把它路由给未收录的 `1688-order`，本知识库只标明边界，不虚构下单命令。

## 典型判断

| 用户表述 | 对象确定性 | 动作 | 路由 |
| --- | --- | --- | --- |
| “搜黑色卫衣” | 未确定 | 浏览 | product-find/text_search |
| “用图找同款” | 有参考物 | 图搜 | product-find/image_search |
| “这个链接帮我比价” | 有参考商品 | 一步比价 | product-find/compare --url |
| “找常州灯具工厂” | 供应商未确定 | 查企业 | source-suppliers |
| “采购 500 个 304 螺丝，谁能供货” | 无 offerId | 发布询盘 | procurement |
| “下单 offerId xxx” | 商品已确定 | 交易 | 转 1688-order；本批不覆盖 |
| “铺到我的抖店” | 商品与店铺逐步确定 | 分销 | 分销或 shopkeeper |
| “报名这个活动” | 活动和商品需确认 | 报名 | marketing-skill |
| “拒签这张采购单” | 采购单已确定 | 状态变更 | 88 生意通，二次确认 |

## A. 搜索与比价

1. 读取对应 capability reference。
2. 识别文本、图片或链接。
3. 无明确比价词：文本走 `text_search`，图片走 `image_search`，链接走 `link_search`。
4. 明确比价：直接走 `compare`，不要先图搜/链搜。
5. 选品后比价，从 `data.similar_products[N].image_url` 取图。
6. 完整输出商品表格，不删行列、不丢 `detail_url`。
7. 生成钉钉表格时使用 16 个字段：商品 ID、名称、主图 URL、详情链接、价格、规格 ID、规格、严选指数、起批量、单位、供应商、销量、库存、促销标签、服务保障、卖点。

该 Skill 无状态；“再便宜一点”等多轮细化要由 Agent 重建完整 query。

## B. 查供应商

1. 从原话提取供应商、品类或地区关键词。
2. 不明确则追问，不自行扩写。
3. 读取 `ali_1688_source_suppliers` reference 后执行。
4. 只展示公司名称、合作方式、服务均完整的记录。
5. 数据块和 Agent 分析分开。

## C. 发布采购询盘

1. 确认没有具体 offerId/链接，也不是普通浏览。
2. 抽取 `offerName`、`count`、`demand`。
3. `count` 只传纯数字，不含单位。
4. 缺哪个字段就追问哪个字段。
5. 三项齐全后按来源规则执行 `procurement`。
6. 失败时不通过网页搜索替代。

## D. 招商活动与商机

活动报名：查活动 → 用户选活动和商品 → 查建议价 → 注意返回单位为分 → 建议价为空则停止 → 展示并等确认 → 构造有/无 SKU 的 `fillFormDataList` → 以元为单位提交。

商机推荐：提取可选关键词和类目 → 查询 → 展示标题、类目、求购数、参考价格 → 必要时提示翻页。

## E. 分销选品与铺货

1. 检查 AK；每个节点先读对应 `reference.md`。
2. 有商品 ID 时跳过选品；文本走关键词选品，图片走图搜。
3. 按能力地图中的超量请求规则拉候选。
4. 查询分销参谋；失败候选静默过滤。
5. 按代发价、30 天分销单量、服务和风险排序。
6. 品牌商品未授权则禁止铺货，并给授权入口。
7. 单店可直接使用；多店必须全部列出并等用户指定；过滤过期店铺。
8. 用户确认商品和店铺后铺货。
9. 只按来源允许的续铺流程询问，不添加泛化“后续建议”。

## F. 分销订单与催发

从意图抽取订单 ID、时间、订单状态、退款状态；无条件时默认当天。展示统计、订单、风险和退款信息。有风险订单时按卖家分组，经旺旺催发；告知通常 5-10 分钟回复。只有用户主动要求时，才用 `task_id` 查询回复。

## G. 88 生意通采购单

典型路径：`account` → `create-order` → `sign-order` → `contract-detail`。查询可直接执行；创建、签署先确认；拒签、失效、退款、确认收货必须二次确认；写后查询最新详情。子账号、合同类交易和支付转网页端。

## H. 店管家

`check` 后按状态分支：未配 AK 先配置；无店铺先开店；授权过期先重授权；正常后 `search` → 用户筛选确认 → `shops` → `publish`。经营问题先加载对应 FAQ reference。

## 停止条件

- 必要输入缺失。
- reference 未读或参数无法确认。
- AK/授权恢复失败。
- 品牌商品未授权。
- 多店铺但用户未指定目标。
- 写入尚未达到该能力的确认要求。
- CLI 失败或空结果；不得编造或转网页搜索补数据。
