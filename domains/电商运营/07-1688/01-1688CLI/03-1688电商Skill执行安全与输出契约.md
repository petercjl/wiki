# 1688 电商 Skill 执行安全与输出契约

## 运行包是执行真相

这些页面是 2026-07-16 快照。第一次命中某能力时，定位当前 Skill 包，完整读取能力 reference，从中取得动作名、参数和示例；不能凭知识库或记忆拼命令。当前 reference 与旧快照冲突时，以当前运行包为准并说明差异。

## AK 与凭证安全

- 不把 AK 明文贴进聊天、截图、日志或版本控制。
- 不上传 `.ak_store.json`、`.device_id`。
- marketing 来源称 AK 使用 PBKDF2、流加密、HMAC 并绑定设备；这是来源描述，执行前仍需检查当前实现。
- 怀疑泄漏时清除凭证并从官方入口重取。
- 不在正式知识或执行报告中记录真实 AK。

## 授权流程按 Skill 区分

| Skill | 来源定义 | 关键限制 |
| --- | --- | --- |
| marketing | `get_ak`/`authorize` 返回 `action: browser_use` 后立即打开 URL | localhost 回调；8080-8089；最长 300 秒；之后查 status |
| 分销 | 未授权时静默 `--get-ak` 并用 browser_use 打开 URL | 不向用户展示授权 URL；失败后才手动配置 |
| product-find | AK 未就绪先 `get_ak`，失败后再人工引导 | 不用浏览器搜索商品替代 API |
| suppliers/procurement/88 生意通 | 错误时按各自话术配置或检查 AK | 不套用其他 Skill 的自动授权方式 |
| shopkeeper | 从 1688 AI 版 APP 获取 AK；刚配置时当前会话可能需环境变量 | 以当前 reference 为准 |

浏览器只用于认证恢复，不等于允许绕过 CLI 抓业务数据。

## 风险与确认门禁

| 能力 | 动作 | 来源要求 |
| --- | --- | --- |
| 商品、供应商、活动、商机、订单/采购单查询 | 读取 | 输入明确可直接执行 |
| 活动报名 | 写入 | 先查并展示建议价，商家明确确认后提交 |
| 分销铺货 | 不可逆写入 | 确认商品和店铺；多店不自动选；品牌未授权禁止铺 |
| 采购询盘 | 创建类写入 | 商品名、数量、需求齐全时来源允许直接执行 |
| 88 生意通创建/签署 | 写入 | 先确认明确意图 |
| 退款、确认收货、拒签、失效 | 资金/状态变化 | 二次确认 |

确认要求按能力分别保留。当前运行包如更严格，采用更严格规则。

## 全局禁止

- 编造商品、企业、价格、规格、库存、链接、订单或店铺。
- 未经同意改写查询或采购意图。
- 失败后自动改变条件、补数据或用搜索引擎旁路。
- reference 未读时猜命令。
- 把 Agent 分析混进工具数据。
- 给未授权品牌商品铺货。

## 输出契约

多数来源使用 `{"success": bool, "markdown": str, "data": {...}}`；marketing 还可能返回 `error_code`、`required_scope`；授权可能返回 `pending`、`action`、`url`。

### 商品搜索

完整输出 `markdown` 表格，不删行列、不丢 `detail_url`、不改格式；分析放表格之后。来源同时出现“钉钉表格后续操作”和被注释禁用的商品墙说明，执行时以当前返回和 reference 为准。

### 供应商

只展示公司名称、合作方式、服务完整的记录。顺序为工具数据 → 来源指定入口 → 可选分析。

### 分销

商品 ID 必须带详情链接；≤3 个商品用卡片，>3 个用表格。铺货结果原样转发 `markdown`。不添加自创“后续建议”，只可进行来源明确允许的续铺询问。

### 88 生意通

数据与分析分层。回答末尾的免责声明应从当前 `common-rules.md` 取得准确文本；来源快照要求以 88 生意通页面、银行和平台实际处理为准。

## 错误恢复

| 信号 | 处理 |
| --- | --- |
| AK 未配置/未就绪 | 走该 Skill 的 get_ak/configure，不跨 Skill 猜流程 |
| 401/签名无效 | 检查 AK 是否过期，重新配置 |
| 参数缺失 | 只追问缺少字段 |
| 429/限流 | 告知等待 1-2 分钟，由用户决定是否重试 |
| 格式异常/500/服务异常 | 输出真实错误，稍后再试，不网页搜索兜底 |
| 图片路径无效 | 让用户检查或重传 |
| 无法取主图 | 按当前 reference 请求图片 URL |
| 沙箱/权限拒绝 | 授权目录或复制到允许的 workspace |
| 店铺未绑/工具过期 | 绑定或续订，不自动换店 |
| 品牌未授权 | 停止铺货，申请授权 |
| 非主账号/未签约实名绑卡 | 转主账号或网页端完成准入 |

## 环境与版本快照

- marketing 描述 Windows 权限不足时把整个 Skill 复制到 workspace；同时称仅依赖标准库，即使文中保留 `pip install -r requirements.txt`。
- marketing 与 product-find 通过 `.env` 的 `SKILL_NAME`、`SKILL_VERSION`、`SKILL_CHANNEL` 上报调用，系统环境变量优先，埋点失败不影响主流程。
- marketing 默认值为 `SKILL_NAME=1688-marketing`、`SKILL_VERSION=1.0.0`、`SKILL_CHANNEL=clawhub`；product-find 快照为 `SKILL_NAME=1688-product-find`、`SKILL_VERSION=1.7.0`、`SKILL_CHANNEL=clawhub`。
- 埋点实现位于 `scripts/_tracker.py` 的 `report_skill_usage()`，由 `cli.py` 的 `main()` 在每次命令后调用；接口为 `POST /api/reportSkillsUsage/1.0.0`，参数是 `apiName=null`、`skillsName`、`version`、`scene=CLI`、`channel`。
- product-find 版本记录从 v1.0.0 到 v1.7.0，加入统一 CLI、测试、比价、URL 比价、表格、`tags` 与 `icTags`；v1.7.0 日期早于 v1.6.0，来源时间线有矛盾，不能推断真实发布顺序。
- product-find 无状态，多轮细化必须由 Agent 重建上下文。
