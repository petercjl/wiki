# 飞刀新版后台能力与只读 CLI

2026-08-11 实际页面确认产品名为“飞刀全批量修改（淘宝版）”。当前新版的主线不是旧教程里的模式、复制和 1688 铺货，而是五组能力：多店管理、自动补库存、自动同步、批量修改和批量导出。

## 当前能力总览

| 能力 | 当前确认内容 | 主要风险 |
| --- | --- | --- |
| 多店管理 | 查询店铺、添加店铺、修改备注、删除店铺，查看出售/仓库商品数量和套餐状态 | 授权码和删除店铺属于敏感或高影响动作 |
| 自动补库存 | 全店规则、指定参与/排除商品、补库存记录、撤单/退款补回 | 可能造成超卖、虚假稀缺或履约偏差 |
| 自动同步 | 源店/目标店、商品关联、同步属性、方向和自动同步日志 | 错误关联会持续扩散，删除关系不可当作暂停 |
| 批量修改 | 商品、SKU、素材、时效、运费、上下架、删除和分类 | 范围选错会影响大量商品 |
| 批量导出 | 按商品条件筛选、立即导出、查看导出记录 | 导出文件可能包含经营敏感数据 |

## 自动补库存

当前页面把补库存分为“全店设置、选择商品设置、查看补库存记录”。规则包括：

- SKU 库存低于阈值时增加指定数量；
- 始终把每个 SKU 固定在指定库存；
- 售罄后补库存并上架；
- 延迟若干分钟补货；
- 低于阈值后停止补货；
- 全店参与、指定参与或指定不参与；
- 未付款订单取消后补回；
- 退款后补回，已发货订单可排除；
- 支持“恢复原样”。

页面把它用于“饥饿营销”，但运营上不能把展示库存当真实可售库存。启用前必须核对真实库存、供应能力、订单锁库、退款和已发货边界。

## 自动同步

当前页面确认三块：同步商品属性、配置商品关联、自动同步记录。

1. 明确源店和目标店。
2. 用商家编码、商品 ID 或标题关键词定位商品。
3. 建立源商品与目标商品的对应关系。
4. 设置自动同步属性和方向。
5. 通过状态和日志持续核对。

当前新版没有显示“分销商模式/店群模式”切换，也没有独立“手动同步”入口。因此，旧教程里的模式选择、单向/双向边界和手动同步步骤只能作为历史能力参考；当前执行应以源/目标和商品关联页面为准。

## 当前批量修改字段

| 组别 | 当前可见字段 |
| --- | --- |
| 商品字段 | 标题、库存、价格、商家编码、品牌 |
| SKU | 添加 SKU、删除 SKU、翻新 SKU、SKU 名称、搜索标题、搜索主图 |
| 素材 | 1:1 视频、1:1 主图、3:4 主图 |
| 交易与归类 | 发货时效、运费模板、上架商品、下架商品、删除商品、店铺分类 |

标题、库存、价格、商家编码和品牌页面都确认有“选择商品修改、上传文件修改、查看修改记录”。选择商品路径可立即修改或定时修改。

通用筛选包括上架/更新日期、商品状态、一级类目、运费模板、店铺分类、价格、库存、销量、商家编码、商品 ID 和标题关键词。商家编码页面明确提示：平台不支持清空编码；不再使用时只能改成其他字符。

## 与视频教程的冲突处理

| 视频教程能力 | 2026-08-11 新版状态 | 知识处理 |
| --- | --- | --- |
| 分销商/店群模式 | 当前菜单不可见 | 保留历史页，执行前复核旧版或服务方 |
| 商品复制与防重复 | 当前菜单不可见 | 不作为新版现行入口 |
| 手动同步 | 当前菜单不可见 | 以自动同步和商品关联为当前确认 |
| 1688 选品、铺货、货源关联 | 当前菜单不可见 | 保留历史页，不推断永久删除 |
| 自动补库存 | 当前新版明确可见 | 新增为当前正式能力 |
| 批量导出 | 当前新版明确可见 | 新增为当前正式能力 |

“不可见”不等于服务端永久删除：可能与版本、套餐、账号、灰度或旧版入口有关。任何真实操作都应再次以当前账号页面确认。

## 只读 API 与 fdcli

当前前端静态发现 59 条路径：21 条确认只读、23 条写入、10 条受限、5 条语义待确认。业务请求统一走 `/api`，请求与响应使用 AES-CBC 加密。

当前只读目录：`/dict/listversion`、`/map/get`、`/map/list`、`/map/product/list`、`/publish/log/list`、`/publish/template/get`、`/publish/template/list`、`/publish/template/listallsimple`、`/shop/getprofile`、`/shop/list`、`/shop/listall`、`/shop/listallsimple`、`/sync/auto/log/list`、`/sync/direction/get`、`/task/list`、`/tool/brand/list`、`/tool/freight/list`、`/tool/product/list`、`/tool/productstatus/list`、`/tool/rootcat/list`、`/tool/shopcat/list`。

本机已建立 `fdcli`，只开放查询：

```text
fdcli capabilities
fdcli doctor --json
fdcli auth status --json
fdcli profile --json
fdcli shops list --json
fdcli products list --shop-id <店铺ID> --json
fdcli api list --json
fdcli api call --path <只读白名单接口> --data '<JSON>' --json
```

硬边界：

- 通用接口调用只允许明确的查询白名单；
- 修改、提交、刷新、上传、暂停、恢复、删除、上下架和同步配置接口一律拒绝；
- 所有查询统一拒绝 `refresh:true`；商品查询固定使用 `refresh:false`，避免触发刷新动作；
- 资料输出隐藏登录 IP，凭证和 Token 永不显示。

## 认证寿命与独立运行

- 当前页面用 `token` Cookie 维持会话，前端设置约 1 天有效期。
- 无会话的外部请求返回 `900005 会话失效`。
- 旧版页面的新版回调包含续期凭证；当前验证可在无浏览器 Cookie 时签发新的短会话。
- 续期凭证在页面刷新后保持一致，但服务端没有公开永久期限。它可能因订购到期、解绑或服务策略变化而失效。
- 配置续期凭证后，`fdcli` 的资料、店铺和商品查询可以脱离 9223；未配置时自动回退到 9223。

当前服务使用 HTTP 而不是 HTTPS，续期凭证和短会话没有 HTTPS 传输保护。只能在可信网络中使用，并把续期凭证视为高敏感数据。凭证若写入本机，文件权限必须为 `600`。
