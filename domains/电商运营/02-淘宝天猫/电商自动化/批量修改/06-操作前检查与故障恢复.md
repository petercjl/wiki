# 批量自动化操作前检查与故障恢复

批量修改、复制和同步的共同风险是：一个错误规则可以快速影响大量商品。安全执行需要把“范围、方向、规则、任务、记录、恢复”串成闭环。

## 提交前六项检查

| 检查项 | 必须回答的问题 |
| --- | --- |
| 范围 | 哪些店铺、商品和 SKU 会被影响？查询为空是否代表全店？ |
| 方向 | 谁是源、谁是目标？是否可能反向覆盖？ |
| 规则 | 修改/复制/同步哪些字段？未勾选字段会怎样？ |
| 时间 | 立即、定时还是持续实时？是否有结束/恢复任务？ |
| 记录 | 去哪里查看任务、详情、失败原因和对应商品 ID？ |
| 恢复 | 能否撤销、一键恢复、反向修改、禁用规则或重新同步？ |

## 分级试跑

1. 先选 1 个商品、1 个目标店和最少字段。
2. 检查目标结果、任务记录和商品详情。
3. 扩到 5—20 个商品。
4. 验证筛选、跨页选择和失败重试。
5. 再运行全店或大批任务。

实时同步还应观察一段时间，确认没有循环覆盖、错误双向传播或 SKU 错配。

## 常见故障路由

### 复制失败

- 检查目标店授权、店铺分类、运费模板和商品必填字段。
- 检查是否已经复制，避免重复任务。
- 从失败记录进入详情，修正后再重新复制。

### 手动同步失败

- 检查源/目标商品是否已建立关系。
- 检查商家编码是否唯一，或实时同步关联是否仍有效。
- 检查 SKU 是否全部对应。
- 检查所选字段是否存在于目标商品。
- 修正后只重试失败记录。

### 实时同步异常

- 先禁用规则，阻止错误继续扩散。
- 核对方向、源商品、目标商品和 SKU 映射。
- 查看同步记录中的状态、商品 ID 和备注。
- 确认无误后重新启用；不需要永久删除关系。

### 批量修改范围错误

- 尚未执行：撤销定时任务或取消未开始任务。
- 已执行：确认当前版本是否提供一键恢复。
- 没有可靠恢复：使用修改前导出值或反向任务恢复。
- 恢复后再次核对受影响商品数量和字段。

## 禁用、删除和撤销的区别

- 禁用：保留规则或对应关系，暂时停止持续动作。
- 删除：移除规则或关系，通常不适合临时暂停。
- 撤销任务：阻止尚未开始的单次任务；已经执行的结果不会自动回滚。
- 重新执行：只解决失败项，不等于撤销先前成功项。

## Agent 执行模板

在执行任何自动化任务前，Agent 应输出：

```text
任务类型：批量修改 / 复制 / 手动同步 / 实时同步 / 1688铺货
源店与目标店：
商品范围与预计数量：
涉及字段：
执行时间与持续性：
去重/关联依据：
试跑范围：
结果记录入口：
失败重试方案：
恢复或停用方案：
需要人工确认的高风险动作：
```

涉及全店、批量价格、上下架、双向同步、删除规则或大规模重试时，必须在提交前再次确认目标和数量。

## 只读核验边界

本机 `fdcli` 只用于查看资料、店铺、商品和接口目录：

- 通用调用只开放查询白名单；
- 修改、上传、刷新、暂停、恢复、删除、上下架和同步配置接口全部拒绝；
- 商品查询固定 `refresh:false`；
- 续期凭证和短会话不显示，资料输出隐藏登录 IP；
- 服务使用 HTTP，凭证独立模式只应在可信网络中使用。

只读 CLI 不能替代真实操作前的范围、方向、试跑和恢复确认。详见 [[domains/电商运营/02-淘宝天猫/电商自动化/批量修改/07-飞刀新版后台能力与只读CLI|飞刀新版后台能力与只读 CLI]]。
