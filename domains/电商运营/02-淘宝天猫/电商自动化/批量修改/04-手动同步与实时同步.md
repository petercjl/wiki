# 手动同步与实时同步

> 版本边界：2026-08-11 新版当前确认的是“自动同步”，由同步商品属性、配置商品关联和自动同步记录组成；当前菜单没有独立“手动同步”，也没有显示分销商/店群模式。下文的手动同步和模式方向来自历史视频。

## 当前自动同步界面

- 必须明确源店铺与目标店铺；
- 可按商家编码、商品 ID 和标题关键词查询；
- 支持添加关联、批量修改和批量删除；
- 关联表展示两侧商品、库存、编码、自动同步属性和状态；
- 当前前端确认有关联列表、商品列表、自动关联、方向查询/更新和自动同步日志接口。

真实操作时，以当前源/目标和关联配置为准，不再先假设“主店/分店”或“上级/下级”。

同步不是复制。复制通常生成目标商品；同步是在已有对应商品之间传播字段变化。先建立商品对应关系，再决定一次性同步还是持续实时同步。

## 选择手动还是实时

| 场景 | 手动同步 | 实时同步 |
| --- | --- | --- |
| 数据变化频率低，只想按需更新 | 适合 | 成本可能不必要 |
| 库存、价格等需持续跟随 | 可作为补救 | 适合 |
| 需要定时批处理 | 适合 | 不属于定时任务逻辑 |
| 商品对应关系不稳定 | 先人工核对 | 不应直接开启 |
| 担心错误持续扩散 | 先手动小范围验证 | 验证后再开启 |

## 商品绑定方式

### 唯一商家编码

两个店铺的对应商品使用相同商家编码，并且编码在各自店铺内唯一时，可以按商家编码绑定。若编码缺失、重复或不一致，不能把它当可靠主键。

### 复用实时同步关联

如果已经在“实时同步数据”中建立了一对一商品关系，手动同步规则可以直接复用该关联。这适合没有唯一商家编码、但已经人工确认过对应关系的商品。

## SKU 对应方法

商品关联后还要确认 SKU 层级：

1. 自动匹配：依据 SKU 编码或名称匹配。
2. 拖拽匹配：把目标 SKU 拖到对应源 SKU。
3. 序号匹配：在目标侧填写源 SKU 序号。

编码和名称都不一致时，自动匹配可能失败。所有 SKU 连线或映射完成后，才提交关联。

## 手动同步流程

1. 新建同步规则并命名。
2. 选择绑定方式。
3. 选择要同步的字段，例如商品状态、库存、SKU、价格、主图/其他图片、属性图片、电脑描述或手机描述。
4. 决定同步完成后是否顺带建立实时同步关系。
5. 选择源店、目标店和源商品。
6. 立即同步或设置定时任务。
7. 在任务列表查看状态；未开始任务可按当前功能尝试撤销。
8. 通过任务 ID 查看同步记录；失败项修正后重新同步。

## 实时同步流程

1. 明确同步方向：哪一侧是源、哪一侧是目标。
2. 查询两侧商品。
3. 自动关联或手动关联商品。
4. 完成 SKU 对应。
5. 选择持续同步字段。
6. 启用规则并观察首批记录。
7. 用状态、商品 ID、备注等条件查询同步记录。
8. 需要暂停时禁用规则，不必删除对应关系；确认不再使用时才删除。

## 方向是硬边界

- 分销商模式：实时同步是上级分销商 → 下级分销商的单向链路，下级变化不能反向写回上级。
- 店群模式：一般以主店为基准向分店同步；来源视频还展示了改为双向同步的能力。双向会扩大错误传播范围，开启前必须确认当前版本、字段冲突处理和主数据归属。

## 批量维护

关联规则可以批量修改字段、批量启用/禁用或批量删除。批量操作前先筛选并核对数量；“禁用”适合临时暂停，“删除”会失去关系，二者不能混用。
