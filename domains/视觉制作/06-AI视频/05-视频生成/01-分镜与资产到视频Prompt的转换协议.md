# 分镜与资产到视频Prompt的转换协议

本协议要求每条视频 Prompt 都能回答：它来自哪条分镜、体现了什么导演意图、使用哪些参考、模型要完成什么时间变化，以及怎样判断结果是否可用。

## 输入合同

```text
镜头编号与场景
镜头任务与观众经验
起始状态、主要动作、结果
景别、机位、构图和一个主运镜
人物、产品、场景、道具和声音参考
前后镜连续性状态
对白、环境声和动作音效
必须出现、不得改变、允许发挥
```

输入中缺少产品事实、人物身份或空间关系时，返回 [[domains/视觉制作/06-AI视频/04-图片与控制资产/index|图片与控制资产]]；缺少镜头任务时，返回 [[domains/视觉制作/06-AI视频/02-导演思维/index|导演思维]]。

## Prompt不是分镜表的全文复制

分镜表保存完整决策，单镜头 Prompt 只携带本次生成必须执行的内容：

| 信息 | Prompt 中的处理 |
| --- | --- |
| 人物、产品、场景静态事实 | 用参考锁定，不重复长篇描述 |
| 镜头任务 | 用一句话确定生成结果的叙事目的 |
| 起始状态与动作 | 写成可观察的时间顺序 |
| 景别、构图与摄影机 | 保留改变观众阅读方式的必要字段 |
| 情绪 | 优先翻译成表情、动作、距离、节奏和光线变化 |
| 连续性 | 写继承状态和本镜结束状态 |
| 声音 | 写环境、动作声、对白声源；分段生成时通常不要 BGM |
| 限制 | 只保留身份、产品事实、空间和已观察失败所需的限制 |

## 转换表

| 导演/分镜决策 | 视频 Prompt 表达 | 验收 |
| --- | --- | --- |
| 慢慢靠近人物内心 | 固定起始景别，缓慢推进；人物完成一个微动作并出现结果 | 推进存在且不变成复杂环绕；动作结果可见 |
| 揭示产品是解决方案 | 先出现问题状态，人物执行产品动作，结果改变人物或场景 | 产品在因果链中出现，结构与操作正确 |
| 保持克制观察 | 摄影机静止或极轻移动，环境持续自然变化 | 模型没有自行加入炫技运镜或夸张表演 |
| 从压迫转向释放 | 动作、空间、光线或运动方向出现明确变化 | 变化发生在规定时间，且能与前后镜衔接 |
| 动作中切镜 | 规定上一镜结束动作相位和下一镜继承相位 | 手、身体、道具和运动方向连续 |
| 对白建立人物关系 | 指定谁看着谁说、声源、回应和排除关系 | 没有变成画外音、错人发声或错误视线 |

## 标准Prompt骨架

```text
【镜头任务】
本镜头用于 {{叙事功能}}，观众应感知 {{观众经验目标}}。

【参考锁定】
人物、产品、场景、道具和当前构图遵循对应参考。
所有可见身份、结构、比例、组件位置、材质、颜色、文字、标识和连接关系遵循参考；不要增加、删除、移动或重新设计可见组成。

【时间与动作】
起始：{{首帧状态}}。
动作：{{一个主要动作链，按发生顺序描述}}。
结果：{{结束时可见状态}}。

【摄影机】
{{景别、机位、构图}}；{{一个主运镜及其叙事动机}}。

【环境与声音】
{{必要环境运动}}。
声音：{{环境声、动作音效、对白及其声源关系}}；不要任何背景音乐。

【连续性与限制】
继承 {{上一镜状态}}；结束时保留 {{下一镜需要的状态}}。
{{身份、产品、方向、空间和已观察失败对应的最小限制}}。
```

一个镜头不能完成时，先判断它是否包含多个自然镜头、独立动作链或互相竞争的参考任务。应拆镜、拆生成段或增加控制资产，不以继续加长 Prompt 作为默认修复。

## 生成前检查

- 镜头任务能否用一句话说清？
- 是否只有一个主要动作链和一个主运镜？
- 参考图各自职责是否明确且兼容？
- Prompt 是否把参考图已有事实重复描述成另一套外观？
- 起始状态、动作顺序和结果是否可观察？
- 对白是否写清声源、对象和视线关系？
- 是否写明上一镜继承状态和下一镜所需结束状态？
- 验收项是否能直接判断通过或失败？

## 生成后验收与修复

按以下顺序检查：

1. 镜头是否完成故事和导演任务。
2. 人物、产品、场景和道具身份是否正确。
3. 构图、动作、运镜和时间顺序是否正确。
4. 对白、环境声和动作声是否正确，是否出现不需要的 BGM。
5. 与前后镜是否连续，是否留下可剪切点。
6. 只有确认具体失败后才增加补丁；每轮只改变一个主要变量。

保存入选素材时同时保存 Prompt、参考清单、模型参数、验收结果和失败候选原因。这样后续剪辑和复盘可以区分“导演判断错误”“资产错误”“Prompt 编译错误”和“模型随机失败”。
