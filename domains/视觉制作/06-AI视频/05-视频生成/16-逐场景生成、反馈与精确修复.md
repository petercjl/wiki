# 逐场景生成、反馈与精确修复

## 生成不是一次成片，而是选镜与修复

同一镜头生成多个批次的价值，在于同时暴露模型的稳定项和随机项。先选可用片段，再决定是重写、补资产、补几何参考还是直接剪掉坏镜头；不要默认整条重生成。

## 失败诊断表

| 症状 | 先检查 | 优先修复 |
| --- | --- | --- |
| 杂物融合、道具变形 | 参考是否冲突、动作是否过多 | 减少在场资产，重写可见关系 |
| 节奏拖沓 | 一个镜头承担太多过程 | 压缩动作或从不同批次取段 |
| 日夜/干湿错误 | 起始状态与光源是否明确 | 补状态锁和环境物理 |
| 人物没有反应 | 动作链只有事件没有表演 | 添加停顿、视线、表情与反应时点 |
| 命中点、站位、方向错 | 文字无法唯一描述几何 | 上传草图或构图参考 |
| 资产中途变回旧状态 | 缺少状态版本 | 新建状态角色表并替换引用 |
| POV 生成出眼睛/睫毛 | 约束过载、主体关系含糊 | 简化为一个连续 POV，并锁首帧结构 |
| 对话轴线漂移 | 缺反打图和固定机位 | 补反向地点资产，锁 180 度规则 |

## 反馈语言

反馈应写成“保留什么、哪里可见地错了、应该变成什么”。例如：保留开头动作；桌上是散纸而非融合杂物；门外为白天；发现地图后先微笑；拍下地图再跑向门。把“更好看”“更有电影感”改成可验收行为。

## 草图优先于十句空间说明

炮弹命中位置、人物站位、运动方向、物体相对距离等二维几何，草图通常比长文字更低歧义。草图不必美观，只需标明相机、主体、目标、轨迹和关键边界。

## 批次混剪

可以从 A 批次取反应、B 批次取起飞或撞击，只要角色状态、轴线、光线、动作接口和声音能接上。若第三镜头破坏流畅度，删除它可能比再生更好；生成质量控制包含剪辑取舍，而不只是 Prompt 优化。
