# 短教学视频读取工作流

适用于约 1—15 分钟的抖音、视频号、教程录屏和口播。目标是在一次处理中建立完整、可核查的证据包。

## 标准主线

### 1. 探测文件

用 ffprobe 记录：

- 时长、分辨率、帧率、旋转信息；
- 视频/音频编码、音轨数量；
- 是否存在内嵌字幕；
- 是否为可变帧率或异常文件。

### 2. 建立时间结构

- 用 PySceneDetect 类能力检测镜头变化；
- 对无明显剪辑的录屏，按固定间隔补采样；
- 开头 10 秒加密采样，因为钩子、痛点和核心承诺常集中在这里；
- 结尾必须采样，识别结论、行动召唤和群聊/课程推广。

推荐最小策略：

- 0—10 秒：每 1—2 秒一帧；
- 主体：每个镜头至少一帧，并保留 5—10 秒均匀兜底；
- 出现快速 UI 操作、提示词或前后对比：对局部区间按 0.5—1 秒加密。

### 3. 本地转写

优先复用本机现有 whisper.cpp 和已安装模型，不重复下载权重。保留：

- 原始 SRT/VTT；
- 纯文本；
- 分段起止时间；
- 语言和工具参数；
- 低置信度或疑似术语错误。

ASR 是候选文本，不是最终事实。

### 4. OCR 分层

短视频至少区分：

1. 作者烧录字幕；
2. 抖音/视频号界面、账号名、点赞评论；
3. 画中软件 UI、提示词、参数；
4. 装饰字、贴纸、二维码和推广信息。

正文总结主要使用 1 和 3。平台 UI 与推广信息单独记录，避免误当课程内容。

### 5. 交叉纠错

优先核对以下高风险词：

- 模型、软件、插件、网站名；
- 英文缩写、数字、版本、价格；
- 提示词和命令；
- 专业术语、同音词；
- 否定词与比较词。

若 ASR 与字幕冲突，回看相邻帧和上下文；若仍不能确认，输出两个候选并标记不确定。

### 6. 编译教学结构

不要按时间线机械复述。将内容编译为：

- 视频要解决的问题；
- 核心方法或观点；
- 操作步骤；
- 案例/前后对比；
- 使用条件和限制；
- 作者没有证明的主张；
- 关键时间点；
- 可执行的下一步。

## 建议证据包

```text
video-evidence/
├── manifest.json
├── probe.json
├── scenes.json
├── transcript.srt
├── transcript.txt
├── ocr.jsonl
├── frames/
├── contact-sheet.jpg
├── evidence-ledger.jsonl
└── report.md
```

`manifest.json` 应记录源文件、SHA-256、工具版本、模型路径或模型 ID、采样策略和产物路径。

## 案例：3D 白模故事板教程

一次本地读取包含：

- 100.08 秒竖屏视频；
- 41 张选择帧、17 个场景代表帧；
- 前 10 秒密集采样；
- 本地 Whisper large-v3-turbo 转写；
- 联系表、SRT 和 manifest。

只听 ASR 时，“3D 白模”曾被识别成“白毛”，模型名也出现误写。结合画面字幕、线稿/白模故事板对比和上下文，才恢复出视频的实际论点：用更接近空间、机位和体积关系的 3D 白模故事板，减少生成模型对线稿的误读。

可迁移规则：教程中的关键术语至少需要“音频 + 字幕/OCR”双通道确认；操作效果还应由前后画面确认。

## 失败与回退

| 问题 | 回退 |
| --- | --- |
| 没有音轨 | 跳过 ASR，增强 OCR、场景和动作读取 |
| 烧录字幕模糊 | 裁剪字幕区域、放大、锐化后 OCR |
| 长镜头导致场景数太少 | 增加均匀帧和 UI 变化检测 |
| 快切漏掉关键提示词 | 对疑似区间加密取帧 |
| ASR 大量幻觉 | 检查静音/音乐段，启用 VAD，并标记无可靠语音 |
| 推广内容污染总结 | 把 CTA、联系方式、课程推广单列 |

## 输出模板

