# Agent 视频理解开源项目与技术选型

本页不是“项目越多越好”的安装清单，而是区分哪些能力适合直接进入本机主线，哪些只应借鉴协议，哪些按广告专项启用。

## 选型结论

| 层级 | 项目 | 推荐处置 | 用途 |
| --- | --- | --- | --- |
| 基础媒体 | FFmpeg/ffprobe | 直接采用，已有 | 解封装、音轨、帧、元数据 |
| 本地 ASR | whisper.cpp | 直接采用，已有 CLI/模型 | 时间戳转写、VAD、离线隐私 |
| 场景切分 | PySceneDetect | 优先接入 | 镜头边界和代表帧 |
| 画面文字 | PaddleOCR | 按需接入 | 中文字幕、PPT、UI、商品文字 |
| 通用语义 | Qwen3-VL | 作为可选 VLM | 视频/多图解释和问答 |
| 时间定位 | VideoITG | 先借鉴协议 | 按问题从大量帧中选择相关片段 |
| 长视频 Agent | LongVideoAgent | 借鉴迭代取证协议 | 字幕定位—视觉查询—回答 |
| 长视频 RAG | VideoRAG | 多视频规模化时评估 | 图索引、层级上下文、跨视频检索 |
| Agent 框架 | OmAgent | 借鉴图工作流 | 分治、多模态节点和 memory |
| 对象连续性 | SAM 2 | 广告专项可选 | 人物/产品/道具跨帧跟踪 |
| 理解评测 | Video-MME-v2 | 借鉴评测维度 | 查找、时间建模、跨时推理、音频 |
| 质量评测 | Q-Bench-Video | 借鉴评测维度 | 技术、美学、时序、AIGC 失真 |

## 为什么“原生视频模型”仍需证据工程

Qwen3-VL 等模型接受本地视频路径，并允许设置 FPS、帧数和视觉 token 预算。这改善了接口，但没有取消采样：

- FPS 太低会漏瞬时动作和文字；
- 长视频会受视觉 token 和上下文预算限制；
- 模型回答仍需要时间定位才能审计；
- 音频、字幕、OCR和对象轨迹仍是独立证据。

因此 VLM 是解释器，不是视频处理管线的替代品。

## 三类需求的最小组合

### 短教学视频

`FFmpeg + whisper.cpp + PySceneDetect + OCR + 可选 VLM`

先完成本地确定性证据包；只有动作、画面关系和复杂 UI 需要 VLM。

### 长教学视频

`短视频基础层 + chunk/章节索引 + 文本检索 + 查询驱动局部取帧`

长期、多视频、多跳问题再增加图索引或 VideoRAG。LongVideoAgent、VideoITG 首先贡献的是协议，不必立刻部署其训练栈。

### 广告片

`场景切分 + 密集关键帧 + 声音/字幕 + 目标检查表 + 参考图比对`

角色/产品连续性问题显著时再加入 SAM 2。质量维度参考 Q-Bench-Video，但最终验收仍以广告目标和参考素材为准。

## 项目能力和局限

### whisper.cpp

- 优点：离线、Apple Silicon 友好、时间戳、可加 VAD；
- 局限：不看画面，术语/品牌/同音词仍需 OCR 校正；
- 本机状态：已有 `whisper-cli` 和 large-v3-turbo 模型，不重复下载。

### PySceneDetect

- 优点：确定性、成本低、适合替代纯均匀抽帧；
- 局限：长镜头、渐变和录屏页面变化可能漏检；
- 使用：场景采样后仍保留均匀兜底。

### PaddleOCR

- 优点：中文场景文字、字幕、文档和 UI 结构；
- 局限：花字、遮挡、运动模糊需要裁剪和增强；
- 使用：输出应保留区域和文本类别。

### Qwen3-VL

- 优点：视频/多图理解、可控制 FPS/帧数/token；
- 局限：权重和算力成本高，仍可能因采样漏证据；
- 使用：优先对候选片段解释，不默认扫描全部长视频。

### VideoITG

- 核心价值：将查询转成时间定位，先粗筛大量帧再精读 Top-K；
- 局限：依赖明确问题；开放式全片理解仍需全局索引；
- 采用方式：先复刻“查询—候选片段—局部观察”协议。

### LongVideoAgent

- 核心价值：MasterAgent 在有上限循环中请求字幕定位、视觉查询或回答；
- 局限：训练和完整复现较重；
- 采用方式：移植工具调用协议、证据轨迹和停止条件。

### VideoRAG

- 核心价值：图驱动索引、层级上下文和自适应检索，适合跨视频知识；
- 局限：索引成本高；
- 采用方式：仅在课程库长期复用、跨视频问答明显时升级。

### OmAgent

- 核心价值：图式工作流、分治、memory、多模态节点；
- 局限：通用框架不自带本地视频证据标准；
- 采用方式：借鉴架构，不要求 SealSeek 迁移框架。

### SAM 2

- 核心价值：提示式视频分割和跨帧对象传播；
- 局限：跟踪“是不是同一对象”不等于判断“是否符合广告目标”；
- 采用方式：产品、角色、道具连续性专项。

### Video-MME-v2 与 Q-Bench-Video

- 前者用于理解能力分解，后者用于感知质量分解；
- 两者是评测思想来源，不是业务验收的唯一分数；
- 不下载数据集也能先采用其分类框架。

## 部署门槛

新工具进入稳定主线前必须回答：

1. 它替代哪个现有失败点？
2. 输入输出能否进入统一时间轴和 manifest？
3. 是否需要权重、GPU、数据集或额外服务？
4. 失败时怎样降级？
5. 是否有覆盖三类视频的回归样本？
6. 能否通过稳定 CLI 调用，而非仅 notebook demo？

下载仓库只代表完成研究，不代表完成部署。
