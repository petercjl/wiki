# 长教学视频分层索引与检索

适用于 1—2 小时以上课程、会议、直播回放和多集课程。核心原则是：不要在每次提问时重新“看完整段视频”，也不要把全片压成固定少量帧。

## 为什么一次性上下文会失败

- 固定帧数会随时长增长而降低时间分辨率；
- 关键证据可能只出现几秒；
- 字幕能定位观点，却看不到 UI 操作和动作；
- 只做章节摘要会丢失数字、例子、限制和反例；
- 把几小时内容一次交给模型，成本高且难以追溯依据。

长视频系统应分成“离线建库”和“在线回答”。

## 离线建库

### 第一层：原始时间资产

- ffprobe 元数据；
- 带时间戳 ASR；
- 内嵌/烧录字幕；
- 镜头或页面变化；
- 音频静音、音乐和说话段；
- 代表帧及 OCR。

### 第二层：可检索 chunk

chunk 不应只按固定分钟切割。优先级：

1. 官方章节或目录；
2. 主题变化和说话人切换；
3. 镜头/PPT 页面变化；
4. 语义段落；
5. 固定时长作为兜底。

每个 chunk 建议保存：

```json
{
  "chunk_id": "ch03-012",
  "start_ms": 3120000,
  "end_ms": 3265000,
  "title": "权重指标的例子",
  "transcript": "...",
  "ocr_terms": ["点击率", "转化率"],
  "visual_summary": "讲师展示后台报表",
  "entities": ["商品卡", "点击率"],
  "frame_refs": ["frames/3124.jpg"]
}
```

### 第三层：层级/图索引

为长课程或跨视频库连接：

- 课程—章节—chunk—时间片；
- 概念—定义—例子—反例；
- 人物/产品/工具—出现位置；
- 一个观点在不同视频中的重复、补充和冲突。

单视频可以使用层级 JSON + 全文/向量检索；跨数十小时、多视频且关系查询明显时，再考虑 VideoRAG 类图索引。

## 在线回答：有上限的迭代取证

借鉴 LongVideoAgent 与 VideoITG 的协议：

1. 解析问题：需要文本事实、视觉事实还是时间推理？
2. `request_grounding`：用字幕、OCR、章节和实体检索候选时间片。
3. `visual_query`：只读取候选区间的密集帧或视频片段。
4. 写入证据账本，判断证据是否足够。
5. 不足则改写查询或扩大邻近时间范围。
6. 达到证据阈值、轮数上限或无新证据时停止。

推荐默认上限为 3—5 轮。每轮必须产生新候选或新证据，否则停止空转。

## 问题路由

| 问题 | 首选检索 | 后续观察 |
| --- | --- | --- |
| “老师如何定义 X？” | ASR/字幕全文检索 | 核对前后语境 |
| “演示中点了哪里？” | OCR/UI 关键词 + 页面变化 | 候选片段密集帧 |
| “先做 A 还是 B？” | 同时检索 A/B | 读取跨时间顺序 |
| “整个课程的方法框架？” | 章节层级 + chunk 摘要 | 抽查代表性原片 |
| “哪些说法互相冲突？” | 概念/实体跨 chunk 聚合 | 回读每个原始时间片 |

## 长课产物

```text
course-index/
├── manifest.json
├── videos.json
├── chapters.json
├── chunks.jsonl
├── transcripts/
├── ocr/
├── frames/
├── embeddings/          # 可选
├── graph/               # 跨视频时可选
└── query-history.jsonl
```

转写、OCR、切分和帧资产是可复用缓存；不要因为问题变化重复计算。

## 回答要求

- 给出视频/章节、时间范围和证据类型；
- 区分课程原话、Agent 归纳和外部知识；
- 数字、阈值、命令和限制回读原片；
- 涉及跨时因果时，明确哪些是时间先后，哪些只是推测；
- 对未检查章节如实标记。

## 何时不需要 VideoRAG

- 单个 10 分钟视频；
- 只需要一次摘要；
- 字幕检索已经能精确定位；
- 构建索引成本高于重复使用价值。

优先采用最小充分架构：本地 ASR + chunk JSONL + 文本检索 + 局部取帧。出现跨视频关系、长期复用和多跳问题时再升级图索引。
