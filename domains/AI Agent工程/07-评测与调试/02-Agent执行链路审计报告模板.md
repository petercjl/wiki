# Agent 执行链路审计报告模板

本模板用于统一记录 AI Agent 的结果验收和过程验收。机器生成部分应保留可定位的步骤编号；语义审计部分必须引用工具、文件或状态证据，不能只引用 Agent 的最终声明。

## 最终分类

| 分类 | 含义 |
|---|---|
| `true-success` | 结果真实存在，过程合规，关键验证通过 |
| `false-success` | Agent 宣称或表面结果成功，但过程绕过契约、缺少验证或不可复现 |
| `clean-failure` | 过程合规地识别了真实能力边界或缺失前置条件 |
| `system-failure` | 工具、集成、打包或调度链路本身异常，失败过程也不可靠 |
| `insufficient-evidence` | 日志、输出物或环境证据不足，不能下结论 |

## 使用规则

- 机器发现只描述可观察事实，不推断不可见环境。
- 没有观察到清理命令时，写“存在残留风险”，不要直接宣称文件一定残留；应继续检查文件系统。
- 最终分类必须同时引用结果证据和过程证据。
- 对重要问题保留修复前后两份报告，不覆盖历史证据。
- 报告中可以包含 thinking，但应遮蔽凭据，不复制系统提示词和完整上下文快照。
