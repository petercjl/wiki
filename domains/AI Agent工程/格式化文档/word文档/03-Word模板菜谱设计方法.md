# Word 模板菜谱设计方法

## 模板的定义

模板不是一份删掉正文的漂亮 DOCX。合格模板应包含：

| 组成 | 回答的问题 |
| --- | --- |
| 内容骨架 | 这种文档依次需要回答什么 |
| 页面原型 | 封面、摘要、章节、数据、结论、附录分别怎样布局 |
| 样式系统 | 每种信息角色调用什么命名样式 |
| 品牌变量 | 字体、颜色、徽标、页眉页脚如何统一 |
| 自动化组件 | 目录、编号、题注、交叉引用、页码怎样维护 |
| 使用说明 | 什么时候使用、怎样填、怎样增删章节 |
| 禁用规则 | 哪些格式组合会破坏可读性或维护性 |
| 验收清单 | 怎样证明文档完成，而不只是成功生成 |

## 先选菜，再选风格

模板一级分类按读者任务：

- **了解**：说明书、概念文档、白皮书。
- **判断**：研究报告、经营复盘、诊断报告。
- **决策**：提案、立项书、商业计划。
- **执行**：SOP、教程、检查表。
- **同步**：备忘录、周报、会议纪要。
- **查询**：手册、规范、参考资料。
- **留档**：合同、制度、研究长文。

视觉风格是第二维：企业稳健、咨询简洁、学术克制、品牌表现、杂志叙事等。同一视觉主题不能替代不同内容骨架。

## 设计流程

### 1. 写任务契约

明确：

- 谁阅读；
- 阅读后要做什么；
- 屏幕、打印还是两者；
- 篇幅和更新频率；
- 是否需要审阅、引用、品牌、保密标记；
- 最终交付 DOCX、PDF，还是两者。

### 2. 定义内容骨架

为每一节写出它必须回答的问题。先验证论证顺序，再决定页面样式。若删掉全部视觉格式后结构仍然清楚，骨架才基本合格。

### 3. 建立页面原型

不要逐页自由发挥。先定义有限的页面类型：

- 封面；
- 摘要/决策页；
- 目录；
- 普通章节首页；
- 正文页；
- 数据页；
- 案例/引语页；
- 结论与行动页；
- 附录。

每种原型规定允许出现的组件、信息密度和视觉重心。

### 4. 建立样式表

最低建议：

- Title、Subtitle；
- Heading 1—4；
- Body、Body First、Body Compact；
- Bullet 1—3、Number 1—3；
- Quote、Callout、Warning、Action；
- Caption、Table Title、Source Note；
- Header、Footer。

名称表达语义，不使用“蓝色大字”“18号黑体”之类外观名称。

### 5. 设置页面与自动化

- 纸张、页边距、默认段落；
- 分节和不同首页；
- 自动目录；
- 多级编号；
- 题注与交叉引用；
- 页码与文档状态；
- 表格跨页和表头重复。

### 6. 写示例内容

模板中保留短而真实的示例，让使用者看到标题长度、表格规模、图题、行动项和分页效果。示例引导内容还应说明“此处回答什么”，而不只写“请输入文字”。

### 7. 做压力测试

至少测试：

- 标题过长；
- 某节没有图、某节有多图；
- 表格跨页和横向页面；
- 内容增删后目录、编号和引用；
- 中文、英文、数字混排；
- 黑白打印；
- 导出 PDF；
- 不同机器缺少品牌字体；
- 评论和修订清理。

## 模板资产包

建议同时保存：

```text
template-name/
├── template.dotx
├── example.docx
├── README.md
├── content-model.md
├── style-map.md
├── page-roster.md
├── qa-checklist.md
└── CHANGELOG.md
```

生成代码或 Agent 只负责调用这些规则。Node.js 包可以实现样式、组件和数据填充，但不应临时发明内容骨架和视觉系统。

## 模板升级条件

出现以下情况时，应把一次性设计升级为正式模板：

- 同类文档开始稳定复用；实践中可把“预计重复三次”作为投入模板化的工作检查点，但不是硬性标准；
- 多人制作导致格式漂移；
- 品牌、合规或打印要求稳定；
- 目录、题注、表格和附录结构反复出现；
- 需要 Agent 自动生成并稳定验收。
