# 格式化文档

本目录研究 Agent 如何把内容编译成结构清晰、易读、美观、可编辑、可维护、可发布的正式文档。它关注的不是某个生成包，而是输出质量：信息如何组织，格式如何选择，模板如何复用，结果如何验收。

## 研究边界

格式化文档包含四层：

1. **内容模型**：文档要帮助读者了解、判断、决策、执行、查询还是留档。
2. **格式系统**：标题、正文、列表、表格、图表、题注、强调等组件如何表达信息角色。
3. **媒介实现**：Word、PDF、电子表格、演示文稿、在线文档和 HTML 各有什么能力与约束。
4. **质量验收**：结构、可读性、一致性、可访问性、协作、打印和发布是否达标。

当前第一阶段只完成 Word 文档研究。未来新增媒介时，应保留上层共同原则，再建立各媒介的专用格式图鉴、模板菜谱和验收规则。

## 后续研究路线

1. 用真实经营复盘文档验证第一版 Word 菜谱。
2. 补齐中文字体、混排、企业内参和咨询报告样本。
3. 研究并反向拆解 DOCX/DOTX 的样式表、主题和节属性。
4. 按同一框架扩展 PDF、电子表格、演示文稿、飞书/企业微信文档和 HTML 报告。
5. 将稳定规则固化到 Node.js 文档工具、CLI 或 Agent Skill，但让实现层引用设计规范，而不取代设计规范。

## Agent 使用原则

- 先确定文档任务、读者、阅读方式和交付媒介，再选模板。
- 先使用语义样式构建结构，再调整视觉参数。
- 对现有文档先诊断内容层级和格式漂移，再修改。
- 美观不能以破坏可编辑性、导航、复制、打印或可访问性为代价。
- 生成完成不等于任务完成；必须渲染检查并按验收清单复核。
