# 网页 UI 设计总则

## 目标

Agent 生成网页时，先解决“用户如何定位、判断和行动”，再处理装饰。好的业务界面应让用户在短时间内回答：我在哪里、现在怎样、哪里异常、下一步做什么、证据是什么。

## 六条原则

1. **结构稳定，业务可变**：稳定继承空间语法与组件合同；指标、图表、表格和操作随任务变化。
2. **信息层级优先**：通过位置、面积、字号、留白和对比表达重要性，不让所有模块同权。
3. **紧凑不等于微小**：密度来自布局与归组，不来自牺牲字号、行高或点击面积。
4. **状态先于装饰**：风险、样本成熟度、数据口径、更新时间和业务状态应比纹理、插画与氛围更先出现。
5. **行动与证据相邻**：建议旁边应有数据依据、影响范围或验证路径，避免只给口号。
6. **渐进披露**：首屏给结论与优先级，表格、详情抽屉和说明页承载深层证据。

## 默认风格：紧凑商务工作台

该风格面向高信息密度、频繁查看和需要做决定的界面。视觉气质为专业、理性、克制、可信，并保留足够的舒适度。

默认采用：

- 浅灰页面背景、白色内容面板、低对比边框；
- 商务蓝作为主色，绿/琥珀/红承担明确状态语义；
- 小圆角、轻阴影或无阴影、规则栅格；
- 系统无衬线字体与清晰数字；
- 左侧导航、顶部工具、中央模块化工作区。

## 适用性判断

| 任务 | 默认采用程度 | 说明 |
| --- | --- | --- |
| 电商经营与投放报告 | 完整采用 | 强调 KPI、异常、行动、口径与明细 |
| SaaS 后台、运营工作台 | 完整采用 | 强调导航、状态、筛选和数据模块 |
| 网页插件、侧边工具 | 缩放采用 | 保留层级、组件和可读性，压缩外壳 |
| 静态分析报告 | 选择采用 | 可保留模块化，但不必制造无效交互 |
| 品牌故事、活动落地页 | 不作为默认 | 应按叙事、品牌和转化目标另选视觉系统 |
| 作品集、杂志与情绪页面 | 不作为默认 | 可复用可读性规则，不强制工作台骨架 |

## 知识库与 Skill 的边界

- 知识库保存为什么这样设计、何时适用、如何判断和如何验收。
- Skill 保存执行主线、设计变量、布局模板、组件资产与确定性验证脚本。
- 两者共享版本与术语，但 Skill 必须自包含，不得依赖本机私有 Wiki 路径才能运行。
- 真实项目的新反馈先记录为证据，只有跨任务稳定成立的结论才升级为规范或 Skill 主线。
