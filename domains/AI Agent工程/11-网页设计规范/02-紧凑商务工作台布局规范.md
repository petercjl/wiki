# 紧凑商务工作台布局规范

## 四个布局支柱

### 1. 左侧主菜单：多区域页面的强规则

当页面包含多个主题区、数据视图或操作流程时，必须使用左侧菜单栏组织，而不是把所有内容纵向堆叠。

- 顶部：产品、工具或报告身份。
- 中部：主视图导航，顺序对应用户的阅读或决策路径。
- 次级区域：快捷操作，与主导航视觉分组。
- 当前页面必须有明确选中状态，不只依赖文字颜色。
- 桌面端优先常驻；窄屏折叠为抽屉，保留可访问的菜单入口。

单页内容很短、没有真实分区时，不要为了套版伪造菜单。

### 2. 左下角：持续可见的全局状态摘要

左下角不是普通页脚，而是跨页面持续可见的核心信息区。适合放：

- 当前业务或任务状态；
- 数据规模、样本成熟度；
- 数据更新时间或抓取状态；
- 异常数量、有效对象数量；
- 当前账号、筛选范围或数据来源。

只放“需要随时看到，但不值得占据主内容区”的信息。控制在 2–4 行，避免变成第二个详情面板。

### 3. 右上角：条件式全局工具区

存在下列元素时，优先放入右上角：

```text
搜索 / 快速跳转 → 时间范围 → 账号或范围切换 → 导出 / 刷新等操作
```

- 工具作用域必须是全局；仅影响一张表格的筛选应留在表格模块内。
- 时间范围应显示完整起止日期或清楚的相对周期。
- 搜索支持快捷键时显示按键提示，但提示文字可低于正文等级。
- 没有搜索或时间维度时不强行占位。

### 4. 中央区域：有权重的豆腐块系统

中央工作区以规则矩形模块为基础：

| 层级 | 典型内容 | 建议跨度 |
| --- | --- | --- |
| 小型块 | KPI、状态、信号快照 | 单个栅格单元 |
| 中型块 | 行动建议、异常清单、维度摘要 | 2–4 个单元 |
| 大型块 | 趋势图、数据表、核心分析 | 半幅或通栏 |
| 通栏块 | 风险提醒、样本说明、关键结论 | 整行 |

模块大小必须表达重要性。不要把所有卡片做成同样尺寸、同样标题和同样视觉重量。

## 推荐页面骨架

```text
┌──────────────┬────────────────────────────────────────┐
│ 产品 / 报告身份 │ 页面身份                  搜索  时间  操作 │
│              ├────────────────────────────────────────┤
│ 主视图导航      │ 页面标题与当前范围                         │
│              │ 样本成熟度 / 风险提醒                     │
│ 快捷操作        │ KPI 豆腐块                             │
│              │ 趋势分析                优先处理          │
│              │ 时间对比                信号快照          │
│              │ 筛选与明细表 / 详情抽屉 / 其他业务模块     │
│ 全局核心状态    │                                        │
└──────────────┴────────────────────────────────────────┘
```

## 桌面布局基线

- 侧栏：约 230px；内容过长时允许 220–260px。
- 顶栏：约 66px；须能容纳页面身份和全局工具。
- 主内容：最大宽度按数据密度决定，左右内边距约 24px。
- 栅格：12 列或可解释的 CSS Grid；模块间距 8–12px。
- 首屏顺序：标题/范围 → 风险或成熟度 → KPI → 趋势与行动。

## 响应式返回规则

1. 先折叠侧栏，再减少栅格列数，最后才压缩内边距。
2. 不通过把正文降到 12px 以下来维持桌面布局。
3. KPI 从横排变为两列或单列；表格允许横向滚动或切换为摘要卡。
4. 右上工具可分两行或进入工具抽屉，但搜索和当前时间范围仍应可发现。
5. 抽屉、弹层和折叠菜单必须能关闭并恢复焦点。
