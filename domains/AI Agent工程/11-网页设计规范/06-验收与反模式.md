# 网页 UI 验收与反模式

## 交付验收清单

### 结构

- [ ] 多区域页面使用左侧导航，选中态清晰。
- [ ] 左下角有必要的全局状态摘要；无有效信息时不伪造。
- [ ] 搜索、时间和全局操作存在时位于右上角，作用域正确。
- [ ] 中央模块按重要性分配面积，不是卡片同权陈列。
- [ ] 首屏能看到对象、周期、可信度、核心 KPI 与主要异常。

### 可读性

- [ ] 100% 缩放下正文、图例、表头、左下状态和快照标签可直接阅读。
- [ ] 重要信息不低于 12px；10–11px 只用于非关键微型界面。
- [ ] 表格行高、段落行高和模块留白足够。
- [ ] 颜色对比清楚，状态不只依赖颜色。
- [ ] 数字、单位、小数位和对齐规则一致。

### 内容与数据

- [ ] 数据范围、更新时间、归因窗口、口径和来源明确。
- [ ] KPI、图表与表格能够对账。
- [ ] 缺失、零值、未投放和暂无数据没有混为一谈。
- [ ] 推断与直接证据被明确区分。
- [ ] 行动建议具体、可验证，并包含复核或停止条件。

### 交互与适配

- [ ] 搜索、筛选、导航、抽屉、命令面板和按钮可操作。
- [ ] 键盘焦点可见，Escape 与焦点恢复行为正确。
- [ ] 1440px 桌面与约 390px 移动宽度均可用。
- [ ] 打印模式隐藏无意义交互，并保留标题、周期、口径和数据。
- [ ] 自包含报告无失效外部依赖，不暴露私有路径或凭证。

## 反模式

| 反模式 | 问题 | 修正方向 |
| --- | --- | --- |
| 装饰型杂志风强套经营报告 | 弱化业务状态和操作密度 | 将视觉风格让位于证据和决策链 |
| 用小字号换取紧凑 | 造成扫描疲劳和信息遗漏 | 保持 12–13px 基线，通过栅格和归组提密度 |
| 巨型标题占据首屏 | 挤压指标与异常 | 控制标题约 25px，把首屏给业务信息 |
| 所有内容都是同尺寸卡片 | 无法判断优先级 | 用跨度、位置和色彩表达权重 |
| 只有颜色表示好坏 | 对色觉和低对比环境不友好 | 加文字、图标、正负号或标签 |
| 只展示 ROI 不展示口径 | 容易把汇总表现误解为可验证效果 | 同时显示成本、成交、周期、归因和样本 |
| 把一个完成版 HTML 当万能模板 | 业务变化时出现无效模块和硬编码 | 继承 tokens、骨架与组件合同，按任务组合 |
| 为了版式伪造搜索、时间或菜单 | 增加无效界面噪声 | 只在真实功能存在时使用相应布局位 |
| 图表是唯一结论载体 | 无法检索、打印或无障碍理解 | 补充文字摘要和表格证据 |
| 外部字体/CDN 成为硬依赖 | 离线报告失效 | 默认系统字体和内联/本地资产 |

## 完成条件

只有当结构、可读性、数据、交互与依赖检查全部通过，且实际业务数据已验证，网页才可标记为完成。截图好看但数据、口径或交互未验证，只能算视觉预览。
